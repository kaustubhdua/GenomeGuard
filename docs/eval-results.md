# Evaluation results

_Generated by `make eval` (`backend/redteam/run_eval.py`). Do not edit by hand: re-run the command and every number below is reproduced from fixed seeds._

Dataset: **synthetic** (600 donors, 3000 variants, seed 1337). Parameters: k_min=20, MAF floor 0.01, bin width 0.05, epsilon budget 1.0, epsilon per release 0.5, at most 25 variants per noised release.

## What these results do NOT show

- All data is synthetic. Real genomes have linkage disequilibrium, population structure and relatives that this generator only approximates, so real attack success could differ in either direction.
- The attackers are simplified and written by the same people as the defences. The triangulation attacker is the shape the monitor was designed to catch; the slow-attacker rows below show where it stops working.
- The beacon experiment is a simplified replication of the update-flip idea (arXiv:2001.08852): no genome clustering is attempted, so the precision and recall reported are not the paper's.
- The benign-traffic archetypes are our assumption of how researchers behave, not measured logs. The false-positive rates must be re-measured on real traffic.
- Epsilon accounting is simple sequential composition, not a formal DP accountant.

## 1. Differencing (tracker) attack

The attacker asks for a cohort of 60 donors that includes the target, then the same cohort without the target, and subtracts the two answers (10 variants, 100 trials). Metric: share of the target's genotypes recovered exactly. `baseline` is guessing the most likely genotype from allele frequency.

| Defence | Accuracy (mean, 95% CI) |
|---|---|
| none | 100.0% ± 0.0% |
| Laplace noise only (epsilon = 1) | 33.3% ± 3.0% |
| transform ladder only (per-query) | 100.0% ± 0.0% |
| ladder + differencing guard | 54.3% ± 3.0% |
| baseline (guess) | 54.3% ± 3.0% |

The guard blocked the second query in 100.0% of trials. Reading: the ladder alone does not stop differencing (each query is judged on its own); the guard does, bringing the attacker back to the guessing baseline.

## 2. Membership inference on released frequencies (privacy vs utility)

Likelihood-ratio test (Sankararaman-style): can an attacker holding a person's genotype tell whether they are in a 100-donor cohort whose allele frequencies were released? AUC 0.5 = no information, 1.0 = perfect. Utility = correlation / mean absolute error between released and true frequencies. `epsilon` is the TOTAL spent on the release (noise scale = 2 x variants / epsilon).

## 3. Many-narrow-queries triangulation

A scripted attacker shrinks a cohort toward one person with nested cohorts, swapping one variant per query. `gap` is the time between queries. The 15-minute window means a patient attacker can evade rate-based detection.

| Monitor | Gap (s) | Frozen | Median queries to first flag | to freeze | Smallest cohort answered |
|---|---|---|---|---|---|
| on | 5 | 100.0% | 5.0 | 8.0 | 76.0 |
| on | 30 | 100.0% | 6.0 | 10.0 | 59.5 |
| on | 120 | 100.0% | 6.0 | 10.0 | 59.5 |
| on | 600 | 0.0% | 9.0 | None | 64.0 |
| on | 1200 | 0.0% | None | None | 22.5 |
| off | 5 | 0.0% | None | None | 22.5 |

Without the monitor, the floor is k_min = 20: the attacker never gets an answer below it. Gaps longer than the window evade the sliding-window detectors; what still limits that attacker is k_min, the differencing guard and the epsilon budget, not the rate/duplicate detectors.

## 4. Beacon update-flip attack (simplified replication)

The attacker snapshots a beacon before and after `update` new donors are added and flags positions that flipped (boolean: absent to present; count: count rose). Precision = flagged positions the victim really carries; recall of rare positions = share of the victim's rare-variant positions flagged. `genomeguard` = boolean beacon with variants below the MAF floor unanswerable.

| Update size | Mode | Mean flipped positions | Precision | Recall (rare positions) |
|---|---|---|---|---|
| 1 | boolean | 0.7 | 1.000 | 0.138 |
| 1 | count | 382.73 | 1.000 | 1.000 |
| 1 | genomeguard | 0.0 | n/a (no flips) | 0.000 |
| 3 | boolean | 1.9 | 0.386 | 0.138 |
| 3 | count | 757.27 | 0.506 | 1.000 |
| 3 | genomeguard | 0.0 | n/a (no flips) | 0.000 |
| 10 | boolean | 6.97 | 0.102 | 0.144 |
| 10 | count | 1220.7 | 0.314 | 1.000 |
| 10 | genomeguard | 0.0 | n/a (no flips) | 0.000 |
| 30 | boolean | 18.5 | 0.036 | 0.151 |
| 30 | count | 1599.88 | 0.239 | 1.000 |
| 30 | genomeguard | 0.0 | n/a (no flips) | 0.000 |

Reading: batching updates (larger update size) lowers the attacker's precision, as the paper suggests; count-level answers leak far more than boolean ones; hiding rare variants removes the flips entirely in this setup.
